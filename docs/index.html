BSQ: cómo se compila y cómo funciona

Un recorrido en orden: primero qué pasa cuando escribes make, y después qué hace el programa, función a función, desde que recibe un mapa hasta que dibuja el cuadrado más grande.

5 + 1archivos .c + .h

0,85 smapa 10 000 × 10 000

0El problema

Recibimos un mapa. La primera línea dice cuántas filas tiene y qué carácter significa vacío, obstáculo y lleno. Hay que encontrar el cuadrado más grande que no toque ningún obstáculo y pintarlo con el carácter de lleno. Si hay empate, gana el que esté más arriba y, después, más a la izquierda.

La cabecera 9.ox se lee así: 9 filas, . vacío, o obstáculo, x lleno. El cuadrado de la salida mide 7 × 7 (en la terminal parece un rectángulo porque los caracteres son más altos que anchos).

Restricciones: solo se pueden usar open, close, read, write, malloc, free y exit, y todo el código debe cumplir la Norma de 42 (sin for, funciones de 25 líneas como máximo, variables declaradas arriba y sin inicializar, llaves en su propia línea, etc.).

1Estructura del proyecto

Cada archivo tiene una única responsabilidad y están ordenados según el momento en que entran en juego durante la ejecución:

ex00/
├── Makefile           # receta de compilación
├── includes/
│   └── bsq.h          # structs, constantes y prototipos compartidos
└── srcs/
    ├── main.c         # 1. punto de entrada: argumentos, archivos, salida
    ├── read_input.c   # 2. leer el archivo/stdin entero a memoria
    ├── parse.c        # 3. interpretar la primera línea
    ├── validate.c     # 4. comprobar que el mapa es válido
    └── solve.c        # 5. encontrar y pintar el cuadrado

2Compilación: qué pasa al escribir make

Del texto fuente al ejecutable bsq, en el orden exacto en que ocurre.

2.1 El Makefile decide qué compilar y en qué orden

MakefileNAME		= bsq

CC			= cc
CFLAGS		= -Wall -Wextra -Werror
INCLUDES	= -I includes

HEADER		= includes/bsq.h
SRCS		= srcs/main.c \
			  srcs/read_input.c \
			  srcs/parse.c \
			  srcs/validate.c \
			  srcs/solve.c
OBJS		= $(SRCS:.c=.o)

all: $(NAME)

$(NAME): $(OBJS)
	$(CC) $(CFLAGS) $(OBJS) -o $(NAME)

%.o: %.c $(HEADER)
	$(CC) $(CFLAGS) $(INCLUDES) -c $< -o $@

clean:
	rm -f $(OBJS)

fclean: clean
	rm -f $(NAME)

re: fclean all

.PHONY: all clean fclean re

make sin argumentos ejecuta la primera regla del archivo, all. A partir de ahí construye un árbol de dependencias y lo recorre de abajo arriba:

bsq
depende de ↑
main.oread_input.oparse.ovalidate.osolve.o
cada uno depende de ↑
srcs/<nombre>.cincludes/bsq.h
  1. all necesita $(NAME), es decir, el archivo bsq.
  2. bsq necesita los cinco .o de $(OBJS). $(SRCS:.c=.o) los obtiene cambiando la extensión de cada fuente.
  3. Cada .o se construye con la regla patrón %.o: %.c $(HEADER). En el comando, $< es el primer prerrequisito (el .c) y $@ es el objetivo (el .o).
  4. Cuando ya están los cinco objetos, se ejecuta la regla de bsq, que los enlaza.

Esta es la salida real de make en un proyecto limpio:

$ make
cc -Wall -Wextra -Werror -I includes -c srcs/main.c -o srcs/main.o
cc -Wall -Wextra -Werror -I includes -c srcs/read_input.c -o srcs/read_input.o
cc -Wall -Wextra -Werror -I includes -c srcs/parse.c -o srcs/parse.o
cc -Wall -Wextra -Werror -I includes -c srcs/validate.c -o srcs/validate.o
cc -Wall -Wextra -Werror -I includes -c srcs/solve.c -o srcs/solve.o
cc -Wall -Wextra -Werror srcs/main.o srcs/read_input.o srcs/parse.o srcs/validate.o srcs/solve.o -o bsq

Las cinco primeras líneas llevan -c: «compila, pero no enlaces». Cada archivo se compila por separado y no sabe nada de los demás salvo lo que declara bsq.h. La sexta línea no lleva -c, así que es el enlazado.

2.2 Las 4 fases por las que pasa cada archivo

Cada línea cc … -c archivo.c recorre por dentro estas fases. Las tres primeras se repiten para cada .c y la cuarta ocurre una sola vez:

Fuentemain.cTexto C escrito a mano.
1 · PreprocesadocppCopia los #include y sustituye las macros.
2 · Compilacióncc1Traduce C a ensamblador y comprueba los warnings.
3 · Ensambladoas → main.oTraduce el ensamblador a código máquina.
4 · Enlazadold → bsqUne los 5 .o y la libc en un ejecutable.

1 · Preprocesado

El preprocesador trabaja solo con texto. Al encontrar #include "bsq.h", busca el archivo en las carpetas indicadas con -I includes y pega su contenido en ese punto. Como bsq.h incluye a su vez <unistd.h>, <stdlib.h>, <fcntl.h> y <limits.h>, el main.c de unas 70 líneas pasa a tener 2 843 líneas (medido con cc -E). Además se sustituyen las macros: BUFFER_SIZE pasa a ser 65536, INT_MAX pasa a ser 2147483647 y O_RDONLY pasa a ser 0.

El include guard (#ifndef BSQ_H / # define BSQ_H / #endif) evita que el contenido se pegue dos veces si algún archivo incluyera la cabecera más de una vez.

2 · Compilación propiamente dicha

El compilador analiza el C ya preprocesado, comprueba los tipos y genera ensamblador x86-64. Aquí actúan los flags obligatorios: -Wall y -Wextra activan casi todos los avisos (variables sin usar, parámetros sin usar, comparaciones entre tipos con y sin signo…) y -Werror convierte cualquier aviso en un error que detiene la compilación. El proyecto compila sin un solo aviso.

3 · Ensamblado

El ensamblador convierte el texto ensamblador en código máquina dentro de un archivo objeto .o. Ese objeto todavía no se puede ejecutar. Las llamadas a funciones que están en otro archivo quedan como símbolos sin resolver: por ejemplo, main.o llama a read_all pero no contiene su código, porque está en read_input.o.

ObjetoCódigo máquinaFunciones que define
main.o721 Bprint_map_error, write_all, process_fd, process_file, main
read_input.o626 Bgrow_buffer, read_all
parse.o937 Bis_printable, parse_number, check_charset, parse_header
validate.o544 Bget_line_length, is_valid_cell, validate_map
solve.o1 079 Bmin_of_three, create_row, process_row, fill_square, solve

4 · Enlazado

El enlazador junta los cinco objetos y resuelve los símbolos: la llamada a read_all de main.o se conecta con su definición en read_input.o, y así con todas. Lo que no está en ningún .o lo busca en la biblioteca estándar de C (libc). Con nm -u bsq se ve exactamente qué toma el ejecutable de fuera:

$ nm -u bsq
                 U __libc_start_main@GLIBC_2.34   # arranque del programa (lo añade cc)
                 U __stack_chk_fail@GLIBC_2.4     # protección de pila (lo añade cc)
                 U close@GLIBC_2.2.5
                 U free@GLIBC_2.2.5
                 U malloc@GLIBC_2.2.5
                 U open@GLIBC_2.2.5
                 U read@GLIBC_2.2.5
                 U write@GLIBC_2.2.5

Esto es una prueba de que solo se usan funciones autorizadas: open, close, read, write, malloc y free. Las otras dos las añade el propio compilador para arrancar el programa y proteger la pila. El resultado es bsq, un ejecutable de unos 6 KB de código y datos.

2.3 Por qué el Makefile no hace relink

make compara la fecha de modificación de cada objetivo con la de sus prerrequisitos y solo rehace lo que está desactualizado:

$ make
make: Nothing to be done for 'all'.
  • Si no ha cambiado nada, no se ejecuta ningún comando, ni siquiera el enlazado. Eso es lo que pide el enunciado.
  • Si solo editas solve.c, se recompila solve.o y se vuelve a enlazar bsq. Los otros cuatro objetos se reutilizan.
  • Si editas bsq.h, se recompilan todos, porque cada .o lo tiene como prerrequisito. Sin esa dependencia, un cambio en un struct podría dejar objetos incompatibles entre sí.
  • .PHONY indica que all, clean, fclean y re son nombres de acciones, no de archivos. Así funcionan aunque exista un archivo con ese nombre.
  • clean borra los .o, fclean borra además bsq, y re equivale a fclean seguido de all.

3Ejecución: el viaje de un mapa

Qué funciones se llaman, en orden, al ejecutar ./bsq mapa.

  1. mainmain.c

    Si no hay argumentos, lee de la entrada estándar (fd 0). Si los hay, procesa cada archivo y escribe una línea vacía entre un resultado y el siguiente.

  2. process_filemain.c

    Abre el archivo con open y obtiene un descriptor (fd).

    Si no existe o no se puede abrir → map error

  3. process_fdmain.c

    Coordina todo lo que sigue. Lo mismo vale para un archivo que para stdin.

  4. read_allread_input.c

    Lee el contenido completo a un único buffer en memoria.

  5. parse_headerparse.c

    Interpreta la primera línea: número de filas y los tres caracteres.

    Cabecera inválida → map error

  6. validate_mapvalidate.c

    Comprueba que todas las líneas miden lo mismo, que hay tantas como dice la cabecera y que solo contienen caracteres permitidos.

    Mapa inválido → map error

  7. solvesolve.c

    Recorre el mapa una sola vez con programación dinámica, encuentra el cuadrado y lo pinta dentro del mismo buffer.

  8. write_allmain.c

    Escribe el mapa resuelto en la salida estándar, normalmente con una sola llamada a write.

  9. free · closemain.c

    Libera el buffer y cierra el archivo. No queda memoria sin liberar en ningún camino, ni siquiera en los de error (comprobado con valgrind).

4El código, archivo a archivo

En el mismo orden en que se ejecuta. El código que aparece aquí es el de los archivos reales, sin la cabecera de 42.

4.1 includes/bsq.h: lo que comparten todos

includes/bsq.h#ifndef BSQ_H
# define BSQ_H

# include <unistd.h>
# include <stdlib.h>
# include <fcntl.h>
# include <limits.h>

# define BUFFER_SIZE 65536

typedef struct s_map
{
	char	*buf;
	long	len;
	char	*grid;
	long	grid_len;
	int		rows;
	long	cols;
	char	empty;
	char	obstacle;
	char	full;
}	t_map;

typedef struct s_square
{
	int		size;
	int		row;
	long	col;
}	t_square;

void	print_map_error(void);
void	process_fd(int fd);
int		read_all(int fd, t_map *map);
int		parse_header(t_map *map);
int		validate_map(t_map *map);
int		solve(t_map *map);

#endif

Es el único archivo que conocen los cinco .c. Contiene tres cosas:

  • Includes y constantes. Dentro del #ifndef la Norma exige un espacio tras la almohadilla (# include). BUFFER_SIZE es el tamaño del primer bloque de lectura.
  • t_map, todo lo que sabemos de un mapa. buf es el archivo entero en memoria. grid no es una copia: es un puntero que señala dentro de buf, justo después de la cabecera. cols y los tamaños son long para que fila × (cols + 1) no se desborde en mapas enormes.
  • t_square, el mejor cuadrado encontrado: su lado (size) y la fila y columna de su esquina inferior derecha (más adelante se explica por qué inferior derecha).

Así queda el buffer en memoria para un mapa pequeño de 3 × 4. grid apunta a la casilla 0 de la primera fila de datos:

Cada fila ocupa cols + 1 bytes (4 caracteres + \n). La celda de la fila 2, columna 1 está en grid[2 × 5 + 1] = grid[11], resaltada arriba. Gracias a esto el programa pinta el cuadrado directamente sobre el buffer y luego lo imprime de una vez, sin copiarlo.

4.2 srcs/main.c: entrada, orquestación y salida

mainpunto de entrada

srcs/main.cint	main(int argc, char **argv)
{
	int	i;

	if (argc < 2)
	{
		process_fd(0);
		return (0);
	}
	i = 1;
	while (i < argc)
	{
		if (i > 1)
			write(1, "\n", 1);
		process_file(argv[i]);
		i++;
	}
	return (0);
}
  • argc < 2 significa que no hay archivos, así que se lee el mapa del descriptor 0 (stdin). Así funcionan ./bsq < mapa y cat mapa | ./bsq.
  • Con archivos, un while (los for están prohibidos) recorre argv[1] … argv[argc - 1].
  • if (i > 1) escribe \n antes de cada archivo salvo el primero, lo que produce exactamente una línea vacía entre resultados, sean soluciones o map error.

process_filestatic

srcs/main.cstatic void	process_file(char *path)
{
	int	fd;

	fd = open(path, O_RDONLY);
	if (fd < 0)
	{
		print_map_error();
		return ;
	}
	process_fd(fd);
	close(fd);
}

Abre el archivo en modo solo lectura. Si open devuelve un número negativo (archivo inexistente, sin permisos, una carpeta…) muestra el error y termina. Si no, delega en process_fd y después cierra el descriptor. Es static porque solo se usa dentro de main.c.

process_fdel director de orquesta

srcs/main.cvoid	process_fd(int fd)
{
	t_map	map;

	if (!read_all(fd, &map))
	{
		print_map_error();
		return ;
	}
	if (parse_header(&map) && validate_map(&map) && solve(&map))
		write_all(map.grid, map.grid_len);
	else
		print_map_error();
	free(map.buf);
}
  • El t_map vive en la pila. El único malloc que perdura es map.buf, y por eso hay un solo free al final.
  • Si read_all falla, ella misma ya ha liberado su memoria, así que aquí basta con mostrar el error y salir con return ;.
  • La condición encadenada usa la evaluación en cortocircuito de &&: si parse_header devuelve 0, ni se llama a validate_map ni a solve. Con una sola línea se consigue que cada fase solo se ejecute si la anterior ha ido bien.
  • map.grid apunta al mapa ya resuelto (sin la cabecera), que es justo lo que hay que imprimir.

write_allstatic

srcs/main.cstatic void	write_all(char *str, long len)
{
	long	written;

	while (len > 0)
	{
		written = write(1, str, len);
		if (written <= 0)
			return ;
		str += written;
		len -= written;
	}
}

write puede escribir menos bytes de los pedidos, por ejemplo con tuberías o salidas muy grandes. Esta función repite la llamada avanzando el puntero hasta escribirlo todo. En la práctica suele bastar una sola llamada, lo que es mucho más rápido que imprimir carácter a carácter.

print_map_error

srcs/main.cvoid	print_map_error(void)
{
	write(2, "map error\n", 10);
}

Escribe el mensaje en el descriptor 2 (la salida de errores, stderr) para no mezclarlo con las soluciones. La longitud 10 es la de "map error\n".

4.3 srcs/read_input.c: leer sin saber el tamaño

No se pueden usar lseek ni fstat, y stdin puede ser una tubería, así que no hay forma de conocer el tamaño de antemano. La solución es un buffer que crece duplicándose.

read_all

srcs/read_input.cint	read_all(int fd, t_map *map)
{
	long	capacity;
	long	bytes;

	capacity = BUFFER_SIZE;
	map->len = 0;
	map->buf = malloc(capacity);
	if (!map->buf)
		return (0);
	bytes = read(fd, map->buf, capacity);
	while (bytes > 0)
	{
		map->len += bytes;
		if (map->len == capacity && !grow_buffer(map, &capacity))
			return (0);
		bytes = read(fd, map->buf + map->len, capacity - map->len);
	}
	if (bytes < 0)
	{
		free(map->buf);
		return (0);
	}
	return (1);
}
  1. Reserva un primer bloque de 64 KB (BUFFER_SIZE).
  2. read rellena la parte libre del buffer y devuelve los bytes leídos: 0 si se ha llegado al final y -1 si hay un error.
  3. Si el buffer se llena exactamente (len == capacity), se duplica con grow_buffer antes de seguir leyendo.
  4. Al salir del bucle, bytes < 0 indica un error de lectura: se libera la memoria y se devuelve 0.
¿Por qué duplicar y no sumar un bloque fijo? Al duplicar, el total de bytes copiados es menor que 2 × el tamaño final, así que la lectura completa cuesta O(n). Con bloques fijos, un archivo de 100 MB provocaría miles de copias cada vez más grandes, con un coste O(n²).

grow_bufferstatic

srcs/read_input.cstatic int	grow_buffer(t_map *map, long *capacity)
{
	char	*new_buf;
	long	i;

	new_buf = malloc(*capacity * 2);
	if (!new_buf)
	{
		free(map->buf);
		return (0);
	}
	i = 0;
	while (i < map->len)
	{
		new_buf[i] = map->buf[i];
		i++;
	}
	free(map->buf);
	map->buf = new_buf;
	*capacity *= 2;
	return (1);
}

Es un realloc hecho a mano, porque realloc no está permitido: reserva el doble, copia byte a byte con while, libera el bloque viejo y actualiza la capacidad. Si malloc falla, libera el buffer antiguo antes de devolver 0, para no perder memoria.

4.4 srcs/parse.c: la primera línea

parse_header

srcs/parse.cint	parse_header(t_map *map)
{
	long	i;

	i = 0;
	while (i < map->len && map->buf[i] != '\n')
		i++;
	if (i == map->len || i < 4)
		return (0);
	map->empty = map->buf[i - 3];
	map->obstacle = map->buf[i - 2];
	map->full = map->buf[i - 1];
	if (!check_charset(map))
		return (0);
	if (!parse_number(map->buf, i - 3, &map->rows))
		return (0);
	map->grid = map->buf + i + 1;
	map->grid_len = map->len - i - 1;
	return (1);
}
  1. Avanza i hasta el primer \n. Al terminar, i es la longitud de la cabecera.
  2. Si no hay \n (i == len) o la cabecera tiene menos de 4 caracteres (al menos 1 dígito y 3 símbolos), el mapa es inválido.
  3. Los tres últimos caracteres son vacío, obstáculo y lleno. Todo lo anterior (i - 3 caracteres) es el número de filas.
  4. grid apunta al byte siguiente al \n y grid_len es lo que queda del archivo.

Ejemplos: con 9.ox se obtienen 9 filas y los caracteres . o x. Con 2123 se obtienen 2 filas, vacío 1, obstáculo 2 y lleno 3; los dígitos también son caracteres válidos.

check_charset e is_printablestatic

srcs/parse.cstatic int	check_charset(t_map *map)
{
	if (!is_printable(map->empty) || !is_printable(map->obstacle)
		|| !is_printable(map->full))
		return (0);
	if (map->empty == map->obstacle || map->empty == map->full
		|| map->obstacle == map->full)
		return (0);
	return (1);
}
srcs/parse.cstatic int	is_printable(char c)
{
	return (c >= 32 && c <= 126);
}

Los tres caracteres deben ser imprimibles (ASCII 32–126, por lo que el espacio y los dígitos valen) y distintos entre sí. Como char tiene signo, los bytes no ASCII son negativos y no pasan el filtro.

parse_numberstatic

srcs/parse.cstatic int	parse_number(char *str, long len, int *result)
{
	long	i;
	int		digit;

	if (len < 1)
		return (0);
	*result = 0;
	i = 0;
	while (i < len)
	{
		if (str[i] < '0' || str[i] > '9')
			return (0);
		digit = str[i] - '0';
		if (*result > (INT_MAX - digit) / 10)
			return (0);
		*result = *result * 10 + digit;
		i++;
	}
	return (*result > 0);
}
  • Solo admite dígitos, así que +5, -5 o 5 son inválidos.
  • Control de desbordamiento antes de multiplicar. result * 10 + digit ≤ INT_MAX equivale a result ≤ (INT_MAX - digit) / 10, y comprobarlo de esta forma evita calcular un valor que ya se haya desbordado. Por eso 2147483647 se acepta y 2147483648 no.
  • return (*result > 0) rechaza el cero: tiene que haber al menos una fila.

4.5 srcs/validate.c: ¿el mapa es correcto?

validate_map

srcs/validate.cint	validate_map(t_map *map)
{
	long	i;
	long	col;

	map->cols = get_line_length(map->grid, map->grid_len);
	if (map->cols == 0)
		return (0);
	if (map->grid_len != (long)map->rows * (map->cols + 1))
		return (0);
	i = 0;
	col = 0;
	while (i < map->grid_len)
	{
		if (!is_valid_cell(map, map->grid[i], col))
			return (0);
		col++;
		if (col > map->cols)
			col = 0;
		i++;
	}
	return (1);
}
  1. cols es la longitud de la primera fila. Si es 0 (no hay mapa, o la primera fila está vacía), el mapa es inválido.
  2. Comprobación en O(1). Si todas las filas tienen cols caracteres y un \n, el mapa ocupa exactamente rows × (cols + 1) bytes. Esta única comparación rechaza al instante que falten o sobren filas, que falte el \n final o que haya basura al final.
  3. Una pasada lineal con un contador de columna col que vuelve a 0 al pasar de cols. Es como recorrer una matriz, pero con un solo índice y sin divisiones.

Las dos comprobaciones juntas garantizan que hay exactamente rows filas de cols celdas válidas cada una.

is_valid_cell y get_line_lengthstatic

srcs/validate.cstatic int	is_valid_cell(t_map *map, char c, long col)
{
	if (col == map->cols)
		return (c == '\n');
	return (c == map->empty || c == map->obstacle);
}
srcs/validate.cstatic long	get_line_length(char *str, long len)
{
	long	i;

	i = 0;
	while (i < len && str[i] != '\n')
		i++;
	return (i);
}

En la posición col == cols (fin de fila) solo se acepta \n. En el resto, solo vacío u obstáculo. El carácter de lleno en el mapa de entrada se considera error, porque el enunciado dice que el mapa solo contiene vacíos y obstáculos.

4.6 srcs/solve.c: el algoritmo

La idea. Para cada celda calculamos dp: el lado del cuadrado vacío más grande cuya esquina inferior derecha es esa celda. Si la celda es obstáculo vale 0. Si no:
dp = 1 + min(arriba, izquierda, diagonal)
El cuadrado solo puede crecer tanto como el más pequeño de sus tres vecinos le permita. Así cada celda se mira una sola vez: O(filas × columnas).

solve

srcs/solve.cint	solve(t_map *map)
{
	int			*dp;
	int			row;
	t_square	best;

	dp = create_row(map->cols + 1);
	if (!dp)
		return (0);
	best.size = 0;
	best.row = 0;
	best.col = 0;
	row = 0;
	while (row < map->rows)
	{
		process_row(map, dp, row, &best);
		row++;
	}
	free(dp);
	fill_square(map, &best);
	return (1);
}

Crea la fila dp a cero, recorre todas las filas del mapa, libera la fila y pinta el mejor cuadrado. Devuelve 0 solo si falla el malloc.

create_rowstatic

srcs/solve.cstatic int	*create_row(long size)
{
	int		*row;
	long	i;

	row = malloc(sizeof(int) * size);
	if (!row)
		return (NULL);
	i = 0;
	while (i < size)
	{
		row[i] = 0;
		i++;
	}
	return (row);
}

Reserva cols + 1 enteros y los pone a 0, ya que calloc no está permitido. Es la única memoria extra del algoritmo: una sola fila, no una matriz. Para un mapa de 10 000 × 10 000 son unos 40 KB en lugar de 400 MB.

process_rowel corazón

srcs/solve.cstatic void	process_row(t_map *map, int *dp, int row, t_square *best)
{
	long	col;
	int		diag;
	int		above;
	char	*line;

	line = map->grid + row * (map->cols + 1);
	diag = 0;
	col = 0;
	while (col < map->cols)
	{
		above = dp[col + 1];
		if (line[col] == map->obstacle)
			dp[col + 1] = 0;
		else
			dp[col + 1] = 1 + min_of_three(above, dp[col], diag);
		if (dp[col + 1] > best->size)
		{
			best->size = dp[col + 1];
			best->row = row;
			best->col = col;
		}
		diag = above;
		col++;
	}
}

¿Cómo se guarda una matriz entera en una sola fila? Antes de sobrescribir dp[col + 1], ese hueco todavía contiene el valor de la fila anterior:

  • above = dp[col + 1] es el valor de arriba, todavía sin sobrescribir.
  • dp[col] es el valor de la izquierda, que ya se ha actualizado en esta fila.
  • diag es el valor de arriba a la izquierda: el above de la iteración anterior, guardado justo antes de pasar a la siguiente columna.

El desplazamiento de +1. La celda col se guarda en dp[col + 1], de modo que dp[0] es siempre 0 y hace de «columna fantasma» a la izquierda del mapa. Como al principio todo vale 0, eso hace también de «fila fantasma» por encima. Así la primera fila y la primera columna no necesitan casos especiales.

El desempate. Se recorre fila a fila y de izquierda a derecha, y el mejor solo se sustituye con > estricto, nunca con >=. Todos los cuadrados de tamaño máximo tienen el mismo lado, así que el primero cuya esquina inferior derecha encontramos es también el de esquina superior izquierda más arriba y más a la izquierda. Es justo lo que pide el enunciado.

line apunta al inicio de la fila dentro de grid (row × (cols + 1)), lo que evita repetir esa multiplicación en cada celda.

min_of_threestatic

srcs/solve.cstatic int	min_of_three(int a, int b, int c)
{
	if (b < a)
		a = b;
	if (c < a)
		a = c;
	return (a);
}

El mínimo de tres valores sin operador ternario, que la Norma prohíbe. Se reutiliza el parámetro a para no declarar más variables.

fill_squarestatic

srcs/solve.cstatic void	fill_square(t_map *map, t_square *best)
{
	int		row;
	long	col;

	row = best->row - best->size + 1;
	while (row <= best->row)
	{
		col = best->col - best->size + 1;
		while (col <= best->col)
		{
			map->grid[row * (map->cols + 1) + col] = map->full;
			col++;
		}
		row++;
	}
}

Con la esquina inferior derecha y el lado, la superior izquierda es (row - size + 1, col - size + 1). Dos while anidados escriben el carácter de lleno directamente en el buffer. Si no hay ningún cuadrado posible (todo obstáculos, size == 0), el bucle no hace nada y el mapa se imprime tal cual.
